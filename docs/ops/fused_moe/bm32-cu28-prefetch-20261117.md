## Saved code change and its measured limits

Issue A1 before loading next-output routes/expert and current channel scales. The two identical measured runs are36.540320 us (wave active32.126792 us, B bandwidth1.566657 TB/s), 0.0304% faster than667abe0 and0.1094% faster than the original36.580352-us reference. SourceELF .text matches the measured repeat byte-for-byte. Preserve A2/B3 slots, priorities, disabled consumer ping-pong, and producer issue exclusion. The change is one moved A1 call plus an explanatory comment; negative trials are not applied.

A1 issue improves CU0 cycle6903 ->6499 and CU28 cycle6867 ->6527. A2 only improves CU0 9867 ->9859 and CU28 9775 ->9763. Thus the earlier A1 does not remove later B/read/scheduling waits. The original CU28 startup trace has a1618-cycle vmcnt(0)-to-next-instruction gap for next-output expert scalarization, with the assembly source location pointing to the next expert gl.load. That full gap is not an end-to-end saving; much overlaps P0 work and other waits.

CU0 per-consumer gap improves1434 ->1368 cycles and max1520 ->1420; merged gap changes677 ->703.
