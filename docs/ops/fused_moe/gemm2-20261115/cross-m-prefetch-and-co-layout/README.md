提前读取下一M A能缩短CU0 SIMD0 C0/C1轮间MMAC间隔1596/2060→976/1144cycle，但当前M MMAC首尾跨度4648/4556→5804/5648cycle，整体变慢。不是预读没有发生，也不能只用局部gap宣称优化。prologue实际A值代替零占位，把v_mov静态数291降到35，整体仍15.761488μs；A/B0/SB一起预读间隔进一步缩到820/500cycle，但当前跨度5836/6488cycle，等待和LDS发射转移到当前计算尾部，16.366972μs。两个M都真实计算，A/B代际、16waves、2048有效MMAC/CU、exec0=0与abarrier等待约束审计通过。

将下一M K0低64行MMAC移到旧M最后32行缩放之前，并提前归还已读完的下一M A/B0 credit，仍保持每个输出K0再K1、((acc*SA)*SB)*weight和BF16结果；实际VGPR214/214，旧版174/174。数值、MMAC计数、A/B真实代际、等待约束及消费者无VMEM/无permlane通过，但17.142592μs，不晋升。轮间store间隔缩短不能证明当前输出发布更快。

Co按消费者打包寄存器排成物理连续vector8，静态ds_write2_b32从42降到10，ds_write_b128从2增到18（含metadata）；P0的16条ds_read_b128变为32条ds_read2_b32。无XOR版bank-conflict1280→7424，18.406380μs。行XOR降到3328，16.487624μs；补充列高位XOR使消费者宽写消失，16.040600μs。仅改变Co的Swizzled(8,4,4)为(32,1,4)，计数降至768，仍15.412320μs。bank计数是整个CU总计，不能把基线1280全归于Co；本组仅Co布局变动，差值可用于定位该变动的影响。不能只优化消费者宽写而忽略P0回读。

P0/P1/消费者仍各4waves，2P2C、117KiB LDS、x4全局散写和工具链保持。LLVM/Triton/PMD沿用最好归档的toolchain-provenance.json；无新工具链修改。负面实现不复制入仓库，comparison.json保存源码和HSACO SHA、原始目录，子目录保存结果与已有审计证据。没有声称对所有变体完成所有审计，文件存在才表示该项执行过。
